**问题描述**：  
应用启动后，主窗口没有显示在屏幕上。进程在任务管理器中可见，但没有可见的窗口界面。

**根本原因**：  
窗口初始化代码在非 UI 线程执行，导致窗口创建失败但没有抛出异常。

**修复方案**：  
使用 `DispatcherQueue.TryEnqueue()` 确保窗口初始化在 UI 线程执行。

## 📚 知识库

### 最佳实践总结

从已修复的 bug 中提取的最佳实践：

1. **线程管理**
   - 所有 UI 操作必须在 UI 线程
   - 使用 `DispatcherQueue.TryEnqueue()` 进行调度
   - 避免在 UI 线程执行耗时操作

2. **错误处理**
   - 关键操作添加 try-catch
   - 记录详细的错误日志
   - 使用调试通知助手追踪状态

3. **AOT 兼容性**
   - 避免使用反射
   - 不使用动态代码生成
   - 优先使用编译时已知的类型

### 调试技巧

1. 使用 `dotnet run --debug-output` 捕获详细日志
2. 使用调试通知助手追踪执行流程
3. 使用 `winapp ui inspect` 检查 UI 状态
4. 在关键位置添加断言和日志
