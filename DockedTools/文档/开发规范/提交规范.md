# Git 提交规范

本文档定义 DockedTools 项目的 Git 提交消息规范，确保提交历史清晰、可追溯。

---

## 🎯 规范目标

1. **清晰的历史**：一目了然地了解项目演进
2. **自动化生成**：支持自动生成 CHANGELOG
3. **快速定位**：快速找到特定功能或修复
4. **团队协作**：统一的提交风格降低沟通成本

---

## 📝 提交消息格式

### 基本格式

```
<类型>(<范围>): <简短描述>

<详细描述>（可选）

<页脚>（可选）
```

### 示例

```
feat(窗口): 添加窗口停靠功能

实现了窗口吸附到屏幕边缘的功能，支持自动隐藏和显示。
用户可以通过拖拽窗口到屏幕边缘来触发停靠。

关联 Issue: #123
```

---

## 🏷️ 提交类型

### 主要类型

| 类型 | 说明 | 示例 |
|------|------|------|
| `feat` | 新功能 | feat(AI): 添加对话记忆功能 |
| `fix` | Bug 修复 | fix(窗口): 修复窗口无法显示的问题 |
| `docs` | 文档更新 | docs(README): 更新安装说明 |
| `style` | 代码格式（不影响功能） | style(代码): 统一缩进为 4 空格 |
| `refactor` | 代码重构 | refactor(AI): 重构技能加载逻辑 |
| `perf` | 性能优化 | perf(渲染): 优化 UI 渲染性能 |
| `test` | 测试相关 | test(窗口): 添加窗口管理单元测试 |
| `build` | 构建系统 | build(依赖): 升级 DevWinUI 到 9.9.5 |
| `ci` | CI/CD 配置 | ci(GitHub): 添加自动化测试流程 |
| `chore` | 其他杂项 | chore(清理): 删除未使用的代码 |
| `revert` | 回滚提交 | revert: 回滚 feat(AI) 提交 |

### 类型选择指南

- **功能开发**：使用 `feat`
- **修复 Bug**：使用 `fix`
- **优化性能**：使用 `perf`
- **代码重构**：使用 `refactor`（功能不变）
- **文档修改**：使用 `docs`
- **格式调整**：使用 `style`（不影响逻辑）

## 📦 范围 (Scope)

### 常用范围

| 范围 | 说明 |
|------|------|
| `窗口` | 窗口管理相关 |
| `AI` | AI 代理和技能 |
| `UI` | 用户界面 |
| `本地化` | 多语言支持 |
| `构建` | 构建和打包 |
| `文档` | 文档系统 |
| `测试` | 测试相关 |
| `依赖` | 依赖管理 |
| `配置` | 配置文件 |

### 范围命名规则

- 使用中文（符合项目约定）
- 简短明确（1-2 个字）
- 与项目模块对应

## ✍️ 描述规范

### 简短描述

**规则**：
- 使用中文
- 不超过 50 个字符
- 使用动词开头（添加、修复、优化、重构等）
- 不以句号结尾
- 描述做了什么，而非为什么

**好的示例**：
```
✅ feat(窗口): 添加窗口停靠功能
✅ fix(AI): 修复技能加载失败的问题
✅ perf(渲染): 优化列表滚动性能
✅ docs(贡献): 更新贡献指南
```

**不好的示例**：
```
❌ feat(窗口): 添加了一个新的功能，用户可以停靠窗口到屏幕边缘。
❌ fix: 修复 bug
❌ 更新代码
❌ WIP
```

### 详细描述

**规则**：
- 与简短描述空一行
- 详细说明修改的内容和原因
- 每行不超过 72 个字符
- 可以分多段
- 可以使用列表

**示例**：
```
feat(窗口): 添加窗口停靠功能

本次提交实现了以下功能：
- 窗口拖拽到屏幕边缘时自动吸附
- 支持自动隐藏和鼠标悬停显示
- 可配置停靠位置（左/右/上/下）
- 保存和恢复停靠状态

实现细节：
使用 Windows API 监听窗口位置变化，当窗口距离屏幕边缘小于
阈值时触发停靠逻辑。状态保存在本地配置文件中。

性能影响：
窗口位置监听使用节流机制，不会影响 UI 性能。
```

### 页脚

**规则**：
- 与详细描述空一行
- 用于关联 Issue、标记破坏性变更等

**格式**：
```
关联 Issue: #123
关闭 Issue: #456, #789
破坏性变更: 窗口配置格式已更改，需要迁移
参考: https://...
```

**破坏性变更示例**：
```
feat(配置): 重构配置文件格式

BREAKING CHANGE: 配置文件格式从 JSON 迁移到 TOML。
用户需要手动迁移现有配置，或删除配置文件重新生成。

迁移指南：参见 docs/migration-guide.md
```

## 🔢 提交粒度

### 原子性提交

**每个提交应该**：
- 只做一件事情
- 是功能完整的（可编译、可运行）
- 独立可回滚

**好的提交**：
```
commit 1: feat(窗口): 添加窗口停靠检测逻辑
commit 2: feat(窗口): 添加停靠动画效果
commit 3: feat(窗口): 添加停靠配置选项
commit 4: test(窗口): 添加停靠功能测试
commit 5: docs(窗口): 更新窗口停靠文档
```

**不好的提交**：
```
commit 1: feat(窗口): 添加停靠功能、修复 bug、更新文档
```

## 📌 特殊情况

### WIP 提交

在功能未完成时，可以使用 WIP 标记：

```
WIP: feat(窗口): 开发中的窗口停靠功能

当前进度：
- [x] 基础检测逻辑
- [ ] 动画效果
- [ ] 配置选项
```

**注意**：WIP 提交应该在功能完成后被 rebase 成规范的提交。

### Merge 提交

使用默认的合并消息或自定义：

```
merge: 合并 feature/window-docking 到 main

完成窗口停靠功能开发，包含以下提交：
- feat(窗口): 添加停靠检测
- feat(窗口): 添加停靠动画
- test(窗口): 添加单元测试
```

### Revert 提交

```
revert: 回滚 "feat(窗口): 添加窗口停靠功能"

回滚原因：
该功能在低配置机器上导致性能问题，需要优化后重新提交。

This reverts commit abc123def456.
```

## 🛠️ 工具和自动化

### Git Hooks

安装 commitlint 检查提交消息：

```bash
# 安装依赖
npm install --save-dev @commitlint/cli @commitlint/config-conventional

# 配置 commitlint.config.js
module.exports = {
  extends: ['@commitlint/config-conventional'],
  rules: {
    'type-enum': [2, 'always', [
      'feat', 'fix', 'docs', 'style', 'refactor', 
      'perf', 'test', 'build', 'ci', 'chore', 'revert'
    ]],
    'subject-max-length': [2, 'always', 50]
  }
};
```

### VS Code 插件

推荐安装：
- **Conventional Commits**：提供提交消息模板
- **Git History**：可视化查看提交历史

## 📊 示例

### 功能开发

```
feat(AI): 添加对话上下文记忆功能

实现了多轮对话的上下文记忆，AI 可以理解前面的对话内容。

功能特点：
- 自动保存最近 10 轮对话
- 支持手动清除历史
- 上下文压缩以节省内存

技术实现：
使用循环队列存储对话历史，当超过限制时自动删除最早的记录。

关联 Issue: #234
```

### Bug 修复

```
fix(窗口): 修复窗口启动时无法显示的问题

问题原因：
窗口初始化代码在非 UI 线程执行，导致窗口创建失败。

解决方案：
使用 DispatcherQueue.TryEnqueue() 确保在 UI 线程初始化窗口。

影响版本: v0.2.0
修复版本: v0.3.0
关闭 Issue: #BUG-20260615-001
```

### 性能优化

```
perf(UI): 优化聊天消息列表渲染性能

优化措施：
- 启用 UI 虚拟化，只渲染可见项
- 使用增量更新代替全量刷新
- 缓存消息模板

性能提升：
- 大量消息场景下 CPU 占用降低 60%
- 滚动流畅度提升明显
- 内存占用减少 30%

测试环境: Windows 11, 1000+ 条消息
```

### 重构

```
refactor(AI): 重构技能加载逻辑

将技能加载逻辑从单一类拆分为多个小类，提高可维护性。

变更内容：
- 创建 SkillLoader 类负责加载
- 创建 SkillRegistry 类管理已加载技能
- 创建 SkillValidator 类验证技能配置

功能行为未变更，纯重构提交。
```

## ✅ 提交检查清单

提交前自检：

- [ ] 提交类型正确
- [ ] 范围准确
- [ ] 简短描述清晰（<50 字符）
- [ ] 使用中文编写
- [ ] 动词开头
- [ ] 没有拼写错误
- [ ] 提交是原子性的
- [ ] 代码可编译运行
- [ ] 已关联相关 Issue
